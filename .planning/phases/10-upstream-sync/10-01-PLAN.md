  <action>
  Create a comprehensive SYSTEM-AUDIT.md that documents:

  **1. System Architecture Overview**
  - The dual-directory structure: root (`commands/`, `agents/`, `get-shit-done/`) contains the "upstream-compatible" versions, while `.opencode/` contains pilot-specific modified copies
  - The core flow: delegation → planning → execution → verification
  - How commands trigger workflows which reference agents

  **2. File-by-File Classification**

  For every file in the repo (excluding `.git/`, `.planning/`, `node_modules/`), classify as:

  - **`ours-only`**: Files that exist ONLY in our fork, not in upstream. These include:
    - `.opencode/` directory and all contents (pilot's modified copies)
    - `requirements/` directory
    - `opencode.json`
    - `.opencode/bun.lock`, `.opencode/package.json`
    - `commands/pilot-judge.md`, `commands/gsd-delegate.md` (our custom commands not in upstream `commands/gsd/` namespace)
    - `commands/gsd-verify-auto.md` (pilot-specific)
    - Any `.deprecated` or `.bak` files

  - **`upstream-take`**: Files where upstream version should completely replace ours:
    - `get-shit-done/bin/gsd-tools.cjs` (new, 5324 lines — critical tooling)
    - `get-shit-done/bin/gsd-tools.test.cjs` (test file)
    - `bin/install.js` (massive upstream rewrite, 1776 lines)
    - `package.json`, `package-lock.json` (upstream deps)
    - `.github/` directory (CI, templates, etc.)
    - `CHANGELOG.md`, `SECURITY.md`, `LICENSE`
    - `assets/` directory
    - `docs/` directory
    - `hooks/` and `scripts/` directories
    - `.gitignore` (take upstream, add our `.opencode/` ignores back)
    - New upstream files we lack entirely

  - **`ours-modified`**: Files that exist in both but we've intentionally changed. These are the hard merge conflicts:
    - `agents/*.md` — all 11 files have pilot-specific frontmatter (model:, tools: object, hex color:, no name:)
    - `commands/*.md` — all command files have pilot-specific frontmatter format AND AskUserQuestion removed
    - `get-shit-done/workflows/*.md` — pilot has auto-mode guards and AskUserQuestion removal
    - `get-shit-done/references/*.md` — pilot has fork notes added
    - `get-shit-done/templates/config.json` — pilot has yolo mode, gates off
    - `README.md` — likely diverged

  - **`shared`**: Files that should merge cleanly or need careful merging:
    - `get-shit-done/templates/` (most template files) — merge upstream improvements, keep pilot customizations

  **3. Conflict Resolution Rules**

  Document the priority order from requirements/upstream-sync.md:
  1. Our delegation prompt (gsd-delegate.md) — ALWAYS ours
  2. Our agent prompts (agents/*.md) — ALWAYS ours
  3. Our workflow prompts (workflows/*.md) — ours for prompting, upstream for tooling/infrastructure
  4. Commands — ours for frontmatter format, upstream for new commands we lack
  5. References — merge both, upstream improvements welcome
  6. Scripts/tooling — ALWAYS upstream

  **4. Upstream New Files Inventory**

  List all files that exist in upstream but NOT in our fork (these just need to be added):
  Run: `git diff --name-only --diff-filter=A dev...upstream/main`
  (Files Added in upstream since merge-base)

  **5. Upstream Deleted Files Inventory**

  List files upstream removed that we still have:
  Run: `git diff --name-only --diff-filter=D dev...upstream/main`

  **6. Key Risk Areas**

  Document the specific merge risks:
  - `commands/gsd/` directory rename (upstream uses `commands/gsd/*.md`, we use `commands/*.md`)
  - The 11 agent files all have frontmatter conflicts
  - Workflow files have both upstream improvements AND our auto-mode patches
  - `bin/install.js` is essentially a new file upstream (1719 insertions)

  **Methodology:** Use `git diff --stat dev...upstream/main`, `git diff --name-only --diff-filter=ADMR dev...upstream/main`, and `diff -rq` commands to build the inventory. Examine file headers to determine classification. Read our `.opencode/` versions to understand what pilot modifications exist.
